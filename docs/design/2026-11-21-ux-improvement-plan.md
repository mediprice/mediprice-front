# 기존 디자인 UX 개선 계획 (2026-11-21)

기존 디자인(Figma 기반 1차, `feature/design-upgrade`)의 생김새는 유지하고, 미처 고려하지 못한 부분을 고친다. 2026-11-21 로컬 통합 환경(백엔드·AI 포함)에서 화면을 직접 재현해 점검했다. 영역은 찾기 흐름, 고르는 흐름, 계정·공통 셋이다. 그 결과를 주제별 단계로 묶었다.

- 원칙: 새 시각 언어를 만들지 않는다. 기존 토큰·부품(`components/ui`)으로 해결한다.
- 단계 안의 항목은 하나씩 커밋한다. 각 항목은 `pnpm check`와 실제 화면(390·1024·1440px)으로 확인한다.
- 표시: ✅ 끝남, ⏳ 진행 중, ⬜ 할 일, 🔁 백엔드나 운영 결정 필요.

## 1단계. 이동과 맥락: 어디서 왔고 어디로 돌아가는가

| #   | 문제                                                                                                                              | 고칠 방향                                                                               | 상태 |
| --- | --------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | ---- |
| 1.1 | 모바일 상단 ‹가 고정 주소로 이동(push)해, 검색어·필터·스크롤을 잃고 기록이 꼬인다                                                 | 앱 안에서 이동해 왔으면 `router.back()`, 처음 들어온 화면이면 `backHref`로 replace      | ✅   |
| 1.2 | 병원 상세 구역 탭(`<a href="#">`)이 기록을 쌓아서, 뒤로 가면 주소와 선택 카드가 어긋난다. 비교 담기가 카드와 다른 항목으로 담긴다 | 탭은 스크롤과 포커스만 하고 해시는 replace한다. 비교 담기에는 카드의 현재 항목을 넘긴다 | ✅   |
| 1.3 | 지도에 갔다 오면 항목 필터가 사라지고, 지도에서 연 병원의 ‹가 지도로 돌아오지 않는다. 지도의 보기 방식과 선택 병원도 풀린다       | 필터 전체를 `back`으로 넘긴다. 지도의 `view`와 `selected`를 URL에 담는다                | ✅   |
| 1.4 | 화면을 옮기는 동안 아무 반응이 없다(`loading.tsx` 0개, 서버 미리 읽기 최대 수 초)                                                 | 항목·병원·검색에 기존 뼈대로 `loading.tsx`를 둔다                                       | ✅   |
| 1.5 | 데스크톱 병원 상세에서 Tab이 지도 조작을 먼저 지난다                                                                              | 본문을 DOM 앞에 둔다. 네이버 로고 링크는 Tab에서 뺀다                                   | ✅   |
| 1.6 | 하위 화면에서 다시 검색할 입구가 없다                                                                                             | TopNav와 SubTopBar에 검색 버튼을 둔다                                                   | ✅   |

## 2단계. 가격을 일관되게: 같은 화면에서 같은 숫자

| #   | 문제                                                                                                                                  | 고칠 방향                                                                                                | 상태 |
| --- | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ---- |
| 2.1 | 항목 요약은 "병원 837곳·최저 1,000원"인데 목록은 799곳이고, 첫 가격은 40,000원이다                                                    | 요약의 범위와 병원 수를 목록과 같은 비교 범위로 맞춘다. 전체 값은 "모든 가격 보기"를 켰을 때 보여 준다   | ⬜   |
| 2.2 | 비교 요약과 "최저" 표시, 선택 카드 범위 막대, AI 카드가 단위가 다른 1,000원을 앞세운다                                                | `comparableBand` 안의 값만 후보로 삼는다. 범위 밖 값은 "단위가 달라 뺐어요"로 표시한다                   | ⬜   |
| 2.3 | 항목 가격 화면에 데이터 기준일이 없다                                                                                                 | 출처 줄에 기준일을 붙이고, 요약 아래에 "실제 진료비와 다를 수 있음"을 둔다                               | ⬜   |
| 2.4 | 항목 없이 담은 병원이 섞이면 비교 가격이 아무 말 없이 사라진다                                                                        | 담긴 항목을 유지하고 그 항목 가격이 없는 병원은 "가격 없음"으로 둔다. 담은 항목이 다르면 알린다          | ⬜   |
| 2.5 | 공유 비교 링크에 사라진 병원이 있으면 비교 전체가 안 보인다. 링크와 내 비교함이 따로 논다. 공유 버튼이 없다. 1곳만 담아도 표를 그린다 | 없는 병원은 빼고 알린다. "이 비교로 비교함 바꾸기"를 두고 공유 버튼을 단다. 1곳이면 병원 추가로 안내한다 | ⬜   |

## 3단계. 검색이 찾아 주게

| #   | 문제                                                                                                                        | 고칠 방향                                                                                                        | 상태 |
| --- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ---- |
| 3.1 | 결과 첫 화면이 가격 없는 상위 코드로 채워진다(MRI, 치료, 초음파, 홈의 MRI·초음파 분야)                                      | 🔁 백엔드가 가격 있는 항목을 먼저 정렬한다. 프론트는 첫 페이지가 모두 가격 없음이면 다음 페이지를 더 읽는다      | ⬜   |
| 3.2 | "더 보기"를 누르면 가격 있는 새 결과가 화면 위쪽에 끼어들고, 펼쳐 둔 목록이 접힌다                                          | 이미 보여 준 순서는 고정하고, 사용자가 연 상태를 유지한다. 추가된 개수를 알린다                                  | ⬜   |
| 3.3 | `도수 치료`, `물리치료`, `임플란트 가격` 같은 검색어가 0건이다                                                              | 🔁 백엔드에서 공백과 꼬리말을 정규화한다. 프론트는 0건이면 한 번 다시 찾고, 분야 칩과 자주 찾는 항목을 보여 준다 | ⬜   |
| 3.4 | 결과 화면의 항목/병원 전환과 지역이 제출해야 바뀐다. 항목이 0건인데 같은 말로 찾은 병원이 있어도 알려 주지 않는다           | 바꾸면 바로 다시 찾는다. "병원 N곳 보기"를 제안한다                                                              | ⬜   |
| 3.5 | 0건 화면이 지역을 넓혀 보라고 하지 않는다. 모바일 분류 화면에는 지역 선택이 없다. 종별 필터에 약국·조산원까지 20개가 나온다 | "전국에서 보기"를 둔다. 분류 머리에 지역 칩을 둔다. 의미 있는 종별만 보여 준다                                   | ⬜   |
| 3.6 | 행별 가격 요약 10개를 모두 받아야 목록이 그려진다                                                                           | 이름을 먼저 그리고 가격 칸만 뼈대로 둔다                                                                         | ⬜   |

## 4단계. 상태와 알림: 기다림, 실패, 끊김, 결과

| #   | 문제                                                                                                     | 고칠 방향                                                                | 상태 |
| --- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ---- |
| 4.1 | 서버 오류가 보이기까지 7~10초 걸린다(5xx 3회 재시도)                                                     | 재시도를 1회로 줄인다. 오래 걸리면 "조금 오래 걸리고 있어요"를 보여 준다 | ⬜   |
| 4.2 | 오류 모양이 화면마다 다르고, 실패 하나에 오류 카드가 둘 나온다                                           | 화면 전체 오류와 부분 오류를 각각 한 가지 모양으로 통일한다              | ⬜   |
| 4.3 | 오프라인이면 버튼이 아무 반응도 하지 않는다                                                              | 셸에 연결 끊김 띠를 띄운다                                               | ⬜   |
| 4.4 | 로그아웃·탈퇴·기록 삭제 뒤 결과 알림이 없다                                                              | 공용 알림(토스트)을 만든다. 기록 삭제는 되돌리기를 둔다                  | ⬜   |
| 4.5 | 세션이 만료되면 쓰던 후기와 의료 프로필이 사라진다                                                       | 만료 로그아웃이면 폼을 유지하거나, 초안을 임시 저장한다                  | ⬜   |
| 4.6 | 로그인하고 돌아와도 하려던 일(관심 추가)이 이어지지 않는다                                               | 하려던 동작을 저장했다가 돌아온 뒤 실행하고 알린다                       | ⬜   |
| 4.7 | 로그인 실패 화면에 "보던 화면으로"가 없다. 404·오류 화면이 셸 밖에 있다. 동의 확인 중에 흰 화면만 보인다 | 돌아가기 버튼, 셸 안의 404, 확인 중 표시를 둔다                          | ⬜   |
| 4.8 | 로딩 뼈대가 실제 화면과 다르다(`/my`, 필터 안내 자리)                                                    | 실제 모양에 맞춘다                                                       | ⬜   |

## 5단계. 모바일·큰 글자·태블릿

| #   | 문제                                                                                                     | 고칠 방향                                                                    | 상태 |
| --- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ---- |
| 5.1 | 글자 200%에서 AI 입력창이 두 글자 폭이 된다                                                              | 입력 줄을 감싸고 최소 폭을 둔다                                              | ⬜   |
| 5.2 | 큰 글자에서 고정 바가 화면의 28~36%를 가린다. 병원 상세 구역 탭 글자가 붙는다. 지도 제목이 세로로 깨진다 | 툴바는 한 줄 가로 스크롤로 하고, 탭 루트의 상단 바는 sticky를 푼다           | ⬜   |
| 5.3 | 모바일 비교함이 꽉 차면 한 곳만 뺄 수 없다. 키보드를 열어도 비교함이 입력을 가린다                       | 비교함 시트에 병원별 빼기를 둔다. 입력 중에는 숨긴다                         | ⬜   |
| 5.4 | 비교표 이름 행이 따라오지 않는다. 2곳만 비교해도 옆으로 밀어야 하고, 이름이 단어 중간에서 끊긴다         | 머리 행을 sticky로 하고, 2곳이면 폭을 맞추고, 이름은 `break-keep`으로 끊는다 | ⬜   |
| 5.5 | 모바일 병원 상세 첫 화면에서 가격이 지도에 밀린다                                                        | 항목이 있으면 지도를 낮춘다                                                  | ✅   |
| 5.6 | 768~1023 태블릿에서 한 열이 772px로 늘어나 이름과 가격이 멀어진다                                        | 목록형 화면을 가운데 열로 모으거나 2열로 만든다                              | ⬜   |
| 5.7 | 의료 프로필 저장 바가 입력칸을 가린다. 법률 문서 표가 모바일에서 넘친다                                  | 하단 바 높이를 변수로 반영한다. 표를 행 카드로 바꾸고 목차 버튼을 둔다       | ⬜   |

## 7단계. 다듬기

| #    | 문제                                                                                                                                                | 고칠 방향                                                                                    | 상태 |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ---- |
| 7.1  | 병원 상세에서 목록 항목을 고르면 맨 위로 튀고, 행에 누를 수 있다는 표시가 없다                                                                      | "목록으로 돌아가기"와 행 끝 › 표시를 둔다                                                    | ⬜   |
| 7.2  | 지도 파란 점이 무엇인지 설명이 없다. 길찾기와 지도 보기가 같은 주소를 연다                                                                          | 범례를 두고, 데스크톱 버튼은 하나로 합친다                                                   | ⬜   |
| 7.3  | 위치를 미루면 서울시청 기준이라는 말이 없다. 거부 상태에서도 "다시 시도"가 나온다. 최대 반경에서 0건이면 할 일이 없다                               | 기준 안내, 허용 방법, 가격 목록으로 가는 버튼을 둔다                                         | ⬜   |
| 7.4  | 관심 카드에서 할 수 있는 일이 열기뿐이다                                                                                                            | 비교 담기와 전화를 둔다                                                                      | ⬜   |
| 7.5  | 후기 쓰기 나가기 확인이 상단 메뉴·뒤로 가기에 걸리지 않는다. 로그인 전 후기 쓰기 화면에 어느 병원인지 나오지 않는다. 없는 후기도 신고 양식이 열린다 | 문서 전체에서 나가기를 감지한다. 병원 카드를 보여 주고 후기가 있는지 확인한다                | ⬜   |
| 7.6  | 내 정보 하위 화면마다 머리 모양이 다르다. 로그아웃이 계정 화면 안에만 있다. 로그인 버튼 무게와 첫 포커스가 제각각이다                               | 머리 규칙을 통일하고, 내 정보 홈에 로그아웃을 둔다                                           | ⬜   |
| 7.7  | 같은 분류 목록을 6가지 이름으로 부른다. 지도 입구가 항목 화면에만 있다                                                                              | "분류"로 통일한다. 홈에 "내 주변 병원" 입구를 둔다                                           | ⬜   |
| 7.8  | 비교 담기 버튼 이름이 병원마다 같다(낭독기). 목록 80페이지에서 좁히기 안내가 없다. 없는 항목 코드면 쓸모없는 다시 시도만 보인다                     | 이름에 병원명을 넣고, 좁히기 안내를 두고, 없는 항목 안내를 보여 준다                         | ⬜   |
| 7.9  | 공유 미리보기가 모든 화면에서 같고, 색이 토큰과 다르다. 문의 경로가 없다                                                                            | 항목·병원별 공유 이미지를 만들고 색을 토큰에 맞춘다. 문의 경로는 🔁 운영자 연락처가 필요하다 | ⬜   |
| 7.10 | 다시 온 사람을 위한 최근 본 항목이 없다                                                                                                             | 기기 안에만 저장해 홈에 칩으로 보여 준다                                                     | ⬜   |

## 이 계획에서 하지 않는 것

- 법률 문서와 AI 안내의 "운영자 확정 필요" 값: 운영자가 정한다(`docs/launch-readiness.md` 4장).
- 다크 모드, 새 색·타이포 체계.
