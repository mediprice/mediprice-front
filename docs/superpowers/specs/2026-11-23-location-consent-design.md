# 현재 위치 사용 동의 설계 (2026-11-23)

## 1. 왜 하는가

주변 병원 찾기(`/map`)는 사용자의 현재 위치로 가까운 병원을 찾는다. 지금은 "서버가 개인위치정보를 받지 않는다"는 설계(컨벤션 §13.5)로 별도 동의 없이 고지만 한다. 사용자(운영자)는 위치를 받아 쓰는 기능이므로 「위치정보의 보호 및 이용 등에 관한 법률」에 맞춰 **위치정보 이용 동의를 제대로 받기로** 정했다.

이 설계는 법률 해석을 확정하지 않는다. 동의·기록·약관을 갖춰 두고, 문구와 보관 기간, 사업 신고는 운영자와 법률 검토가 정한다.

## 2. 정한 것 (사용자 결정)

- **현재 위치는 로그인 회원만 쓴다.** 비로그인 사용자는 지금처럼 지역을 고르거나 지도를 옮겨 찾는다.
- **처음 "내 위치 사용"을 누를 때 동의를 받는다.** 가입 동의 화면에는 넣지 않는다.
- **동의는 계정에 기록하고, 내 정보에서 철회할 수 있다.** 기존 동의 구조(`user_consent`, `/api/users/me/consents`)에 선택 항목 `LOCATION`을 더한다.
- **좌표는 지금처럼 다룬다.** 약 1km로 흐려 로그인 정보 없이 보내고, 서버는 저장하지 않는다. 정확한 좌표는 기기 안에서만 쓴다.
- **이용 사실은 좌표 없이 기록한다.** "회원 N이 언제 주변 병원 찾기에 위치를 썼다"만 남긴다. 보관 기간은 운영자가 정한다.
- **위치기반서비스 이용약관 페이지를 새로 만든다.** 운영자가 정할 값은 "운영자 확정 필요"로 비워 둔다. 법 조항 문구를 지어내지 않는다.

## 3. 고려한 방법

| 방법                        | 내용                                                | 장단점                                                                                                 |
| --------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| A. 비로그인도 허용          | 동의 화면 후 계정 없이 동의 기록(시각·버전·익명 ID) | 편하다. 누가 동의했는지 증명하기 어렵고 철회를 관리할 대상이 없다                                      |
| **B. 로그인 회원만 (선택)** | 동의를 계정에 기록, 내 정보에서 철회                | 동의 증명과 철회가 분명하고 기존 동의 구조를 그대로 쓴다. 처음 쓰는 사람에게 로그인 한 단계가 늘어난다 |

B를 골랐다: 동의의 증명·철회가 법적 동의의 핵심이고, 비로그인 사용자도 지역 선택으로 같은 정보를 볼 수 있다.

## 4. 목표 / 하지 않는 것 / 실패로 보는 것

- 목표
  - 로그인 + 유효한 위치 동의 + 브라우저 권한, 세 가지가 모두 있을 때만 현재 위치를 읽는다.
  - 동의 화면에 수집·이용 고지 항목(목적, 항목, 보유·이용 기간, 거부할 권리와 불이익)과 약관 링크를 보인다.
  - 동의·철회·이용 기록이 서버에 남고, 내 데이터 내려받기에 포함된다.
- 하지 않는 것
  - 정확한 좌표를 서버로 보내거나 저장하는 것.
  - 위치기반서비스사업 신고 대행, 법률 문구 확정.
  - AI 상담의 장소 이름(네이버 지역 검색) 처리 변경 — 별도 검토 항목으로 남긴다.
- 실패로 보는 것
  - 브라우저 권한이 이미 "허용"이라는 이유로 로그인·동의 없이 위치를 읽는 것(지금 코드는 지도 진입 시 바로 찾는다).
  - 비로그인 사용자가 지도를 못 쓰게 되는 것(지역 선택·지도 이동은 그대로 돼야 한다).
  - 동의를 철회했는데 다음 방문에 위치를 읽는 것.

## 5. 동작

### 지도 화면 흐름

```
지도 진입
 ├─ 로그인 + 위치 동의 유효 + 브라우저 권한 granted → 바로 현재 위치로 찾기 (지금과 같음)
 └─ 그 밖 → 지역 중심으로 보여 주고 "내 위치 사용" 버튼만 둔다 (자동으로 묻지 않음)

"내 위치 사용" 누름
 ├─ 비로그인 → 로그인 창. 로그인 뒤 같은 지도로 돌아오면 이어서 아래 단계 (15분 안, 기존 pending-favorite와 같은 방식)
 ├─ 위치 동의 없음/버전 바뀜 → 위치 동의 창
 │     동의 → 동의 저장 → 브라우저 권한 요청 → 위치 찾기
 │     닫기/거부 → 지역 기준 그대로 (안내 띠: 지역 기준으로 보여 드려요)
 └─ 동의 있음 → 브라우저 권한 요청(필요하면) → 위치 찾기

위치를 찾으면 → 이용 기록 1건 저장(실패해도 검색은 계속, 다음 찾기 때 다시 시도하지 않음) → 흐린 좌표로 주변 병원 조회(지금과 같음)
```

- 지금의 "현재 위치를 사용할까요?" 안내 창(`map.location.prompt*`)은 위치 동의 창으로 바뀐다. 동의가 이미 있으면 브라우저 권한 창만 뜬다.
- 브라우저 권한이 denied면 지금처럼 설정을 바꾸는 방법을 안내한다(동의는 그대로 둔다).
- "지금은 안 할래요"를 세션에 기억하는 동작(`PROMPT_DISMISSED_KEY`)은 없앤다. 자동으로 묻지 않으므로 필요 없다.

### 위치 동의 창

```
┌ 위치정보 이용 동의 ─────────────────────┐
│ 가까운 병원을 찾을 때만 현재 위치를 써요.  │
│ 목적   주변 병원 찾기와 거리 표시          │
│ 항목   현재 위치(서버에는 약 1km로 흐려 보냄) │
│        위치를 쓴 날짜·시각(좌표 없이)       │
│ 보유   좌표: 저장하지 않음                  │
│        이용 기록: {N}일 (운영자 확정 필요)   │
│ 거부   동의하지 않아도 지역을 골라 찾을 수   │
│        있어요                             │
│ [위치기반서비스 이용약관 보기]              │
│ [ ] 위치정보 이용에 동의해요 (필수)          │
│              [취소]  [동의하고 위치 찾기]   │
└───────────────────────────────────────┘
```

- `ResponsiveDialog`(모바일 시트·데스크톱 모달), 체크하기 전에는 확인 버튼 비활성.
- "(필수)"는 "이 기능을 쓰려면 필요하다"는 뜻이다. 서버에서는 선택·철회 가능 항목(`required=false`)이다.
- 문구는 `map.locationConsent.*`, 보유 기간 값은 `legal-facts.json`에서 읽는다(없으면 "운영자 확정 필요").

### 내 정보에서 철회

- `/my/account`에 "위치정보 이용 동의" 줄: 상태(동의함·날짜 / 안 함), 동의함이면 "철회" 버튼(확인 창). 철회 뒤 지도는 다시 지역 기준으로 시작한다.
- 의료 프로필 동의 철회와 같은 API(`DELETE /api/users/me/consents/LOCATION`)를 쓴다.

## 6. 백엔드 (mediprice-backend, dev 기준 새 브랜치)

- `ConsentType.LOCATION(false)` — 선택·철회 가능. 철회 시 따로 지울 데이터는 없다(이용 기록은 보관 기간 동안 남긴다).
- 설정 `app.consent.versions.location: ${CONSENT_LOCATION_VERSION:<약관 시행일>}` — FE `LEGAL_DOCUMENT_VERSIONS.LOCATION`과 같은 값.
- 마이그레이션 `V6__location_consent.sql`
  - `user_consent.consent_type` check 제약에 `LOCATION` 추가(V5처럼 이름과 관계없이 지우고 다시 만든다).
  - `location_usage_log` 테이블: `id`, `user_id`(**FK 없음** — 탈퇴해도 보관 기간 동안 남긴다, `admin_audit_log`와 같은 방식), `purpose`(`NEARBY_HOSPITALS`), `consent_version`, `used_at`(timestamptz). 좌표·IP는 넣지 않는다. 인덱스 `(user_id, used_at)`, `(used_at)`.
  - 탈퇴(`UserService.withdraw`)는 이 기록을 지우지 않는다(사용자 결정). 보관 기간이 지나면 자동 삭제 작업이 지운다. 탈퇴 안내·처리방침에 "탈퇴해도 위치 이용 기록은 보관 기간 동안 남는다"를 적는다.
- API `POST /api/users/me/location-usages` (로그인 필수) 본문 `{ "purpose": "NEARBY_HOSPITALS" }` → 204.
  - 유효한 `LOCATION` 동의(현재 버전)가 없으면 403 `LOCATION_CONSENT_REQUIRED`.
  - ApiDocs 패턴(§9), IP 속도 제한은 기존 `/api/**` 제한으로 충분.
- `/api/hospitals/nearby`는 바꾸지 않는다(로그인 정보 없이 흐린 좌표). 서버가 이 조회와 이용 기록을 묶지 않는다.
- 보관 기간 자동 삭제: `RetentionTarget`에 `location_usage_log`(`RETENTION_LOCATION_USAGE_DAYS`, 기본 비어 있음 = 지우지 않음) 추가.
- 내 데이터 내려받기(`/api/users/me/export`)에 위치 동의 이력과 이용 기록 포함.
- `docs/operations.md`에 항목 추가, dev DB에는 Flyway(이미 이력 테이블 있음)로 적용한다 — 적용은 다시 승인을 받는다.

## 7. 프론트엔드 (mediprice-frontend, `feature/location-consent`)

- `LEGAL_DOCUMENT_VERSIONS.LOCATION`, `ConsentType`에 `LOCATION` 추가(동의 API 스키마).
- `features/map`: 위치 사용 조건(로그인·동의·권한)을 판단하는 순수 함수와 테스트, 위치 동의 창, 이용 기록 mutation(`untyped-request` + zod, 생성 타입 갱신 전까지).
- `use-map-search.ts`: 진입 시 자동 찾기를 "로그인 + 동의 + granted"일 때만. 버튼 흐름은 5장.
- 로그인 뒤 이어 하기: `pending-favorite`과 같은 방식의 `pending-location`(sessionStorage, 같은 경로·15분).
- `/location-terms` 페이지(`(sub)`), 법률 문서 공통 부품(`LegalDocument`, `FactList`, `PendingFact`) 사용. 바닥글·처리방침·동의 창에서 링크.
- 처리방침 14항, 수집 항목 표(위치 줄), 보유 기간 표를 새 흐름에 맞게 고친다. 처리방침 내용이 바뀌므로 `PRIVACY` 버전·시행일을 올린다(FE `LEGAL_DOCUMENT_VERSIONS.PRIVACY`, BE `CONSENT_PRIVACY_VERSION` 기본값, 관련 테스트). 기존 회원은 다음 로그인 때 필수 동의를 다시 거친다 — 출시 전이라 영향이 없다. 이용약관(TERMS)은 위치 약관을 따로 두므로 바꾸지 않는다.
- 탈퇴 안내(`/my/account` 탈퇴 확인 문구)에 위치 이용 기록 보관을 한 줄 더한다.
- `legal-facts.json`: `retention.locationUsageDays`(null), 약관에 필요한 운영자 값(예: `locationService.reportNumber` 위치기반서비스사업 신고번호, null). `pnpm launch:check`가 null을 잡는다.
- `/my/account` 동의 줄과 철회.
- 컨벤션 §13.5를 새 설계로 고친다.

## 8. 위치기반서비스 이용약관 (구조만, 문구는 법률 검토)

1. 목적 2. 서비스 내용(주변 병원 찾기, 거리 표시) 3. 이용 요금(무료) 4. 개인위치정보의 이용·보유(좌표 미저장, 이용 기록 보관 기간 = 운영자 값) 5. 동의와 철회 방법 6. 이용자의 권리(열람·고지·정정 요구) 7. 만 14세 미만(가입 불가로 해당 없음 — 기존 최소 나이 값 사용) 8. 사업자 정보(상호·주소·연락처·위치기반서비스사업 신고번호 = 운영자 값) 9. 시행일.

- 조항 번호·법 인용은 넣지 않고 사실만 쓴다. 법률 검토 뒤 고친다.

## 9. 운영자·법률 검토로 남기는 것

- 위치기반서비스사업 신고와 신고번호.
- 이용 기록 보관 기간, 약관·동의 문구 최종본.
- 1km 흐린 좌표를 로그인 정보 없이 보내는 구조에서도 개인위치정보로 볼지 — 이번 설계는 보는 쪽으로 대비한다.
- 서버·프록시 접근 로그에 nearby 요청의 쿼리(좌표)와 IP가 함께 남는지 확인(배포 서버 설정, 코드 밖).
- AI 상담 장소 이름(네이버 지역 검색 전달)의 고지 방식.

## 10. 검토 중 정한 것

- 사용자 결정: 탈퇴해도 위치 이용 기록은 보관 기간 동안 남긴다(FK 없음, 자동 삭제 작업이 지움).
- 설계자 판단(사용자 확인 전 기본값): 처리방침 버전을 올린다, "(필수)"는 기능 기준 표시, 이용 기록 저장 실패는 재시도하지 않는다.

## 11. 빌더에게 맡기는 것

- 컴포넌트·파일 이름, 동의 창 세부 배치(기존 동의 창 스타일을 따른다).
- 이용 기록 저장 실패 시 재시도 여부(기본: 다시 하지 않음).
- 테스트 범위(순수 함수와 API는 반드시, 화면은 Playwright로 390·1440 확인).
